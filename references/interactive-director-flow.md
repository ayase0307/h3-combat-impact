# 雙軌運作流程：靜默自動增強 ＋ 互動式分階段導演（v4.0）

> 本檔是 `SKILL.md` 第零階段的完整條文：怎麼判斷走哪一軌、軌道 A 內部要靜默完成哪些事、軌道 B 三階段的標準話術，以及《影片內容與時間軸主要動作概要》的標準模板。
> 上游導演內核（事實帳本、9 大載體、因果鏈）見 `fight-directing-contract.md`；滑塊數學見 `comfyui-dials-guide.md`；素材情境選單見 `guided-mode.md`。

## 0. 名詞對照（避免字母撞名）

本技能裡有好幾組 A/B，意思完全不同，寫話術時一律帶上前綴：

| 寫法 | 指的是 | 出處 |
|---|---|---|
| **軌道 A／軌道 B** | 靜默自動增強／互動式分階段導演（本檔） | `SKILL.md` 第零階段 |
| **模式 A／模式 B** | 原創導演／參考片逆向＋衍生（入口內容） | `SKILL.md` 1.1、`reverse-and-remix.md` |
| **A 檔／B 檔** | 美型冷靜微表情／粗獷咆哮表情 | `facial-performance.md` |
| **1-A … 1-E、2-A … 4-C** | 軌道 B 階段 1 的四大維度選項（維度編號＋字母） | 本檔 §2 |
| **情境 S1 … S6** | 依手頭素材推薦的六種拍法 | `guided-mode.md` |

軌道與模式是兩個獨立維度：軌道決定「要不要停下來問」，模式決定「從哪裡取得動作內容」。軌道 B 也可以走模式 B（選項 1-E）。

## 1. 雙軌判定（收到訊息先跑這一步）

```
訊息涉及打鬥／武俠仙俠／刀劍兵刃／怪獸機甲／爆氣鬥氣／力場衝擊波／大招特效／高速追逐的提示詞或影片？
 └─ 否 → 本技能不介入
 └─ 是 ↓
① 點名本技能（h3-combat-impact、「用武戲技能幫我…」「用打鬥導演技能…」）？
② 詢問技能用法（「這個技能怎麼用」「有哪些功能」「能做什麼」）？
③ 只丟參考圖、或只有模糊想法（「幫我拍一段帥氣打鬥」「來點炫的」）？
 └─ 任一為是 → 軌道 B · 互動式分階段導演
 └─ 全部為否，且已給出明確角色／場景／動作意圖 → 軌道 A · 靜默自動增強
```

### 1.1 優先序（衝突時這樣裁決）

| 狀況 | 走哪軌 | 做法 |
|---|---|---|
| 點名技能，同時已把角色、場景、招式講清楚 | **軌道 B** | 階段 1 **預填**使用者已講的維度，只列一行讓他確認；**階段 2 閘門絕不跳過** |
| 軌道 B 中使用者說「你決定」「都用推薦」 | **軌道 B** | 階段 1 全採推薦預設，直接進階段 2 交概要；**仍要停下來等確認** |
| 使用者在同一則訊息明確說「不用給我看概要／直接出」 | **軌道 A** | 使用者明確放棄閘門才可跳過；交付時附上一份精簡時間軸供事後查核 |
| 未點名、需求清楚，但缺一項關鍵素材（例如雙人對打只給一張圖） | **軌道 A** | 只問一句缺的東西（或依 `fight-directing-contract.md` §1.3 補最小化對手並註明），不彈選單 |
| 只詢問用法 | **軌道 B** | 先用三句話介紹雙軌與能做的事，再直接進階段 1 選單 |
| 修改既有提示詞（「把第 3 鏡改成踢擊」） | **軌道 A** | 直接改並重跑驗證；改動牽涉勝負或整體節奏時，回報改動後的時間軸 |

**判斷原則**：軌道 A 的價值是「零打擾」；軌道 B 的價值是「使用者在花 GPU 之前看得到並改得到動作設計」。點名技能、問用法、想法模糊，都表示使用者想參與設計，所以走 B。

## 2. 軌道 A · 靜默自動增強（Silent Auto-Enhance）

不彈選單、不解釋流程，在內部依序完成下列檢核，然後直接交付：

| # | 內部動作 | 依據 |
|---|---|---|
| 1 | 時長路由（15s 五段／≤10s 四段／>15s 三表）與節奏模式（六拍／連續對轟／ULTRA_SPEED） | `SKILL.md` 1.2、2.4 |
| 2 | 五級事實帳本、武器與能力零推斷、9 大載體路由 | `fight-directing-contract.md` |
| 3 | 姿態—位移防滑律：跪蹲馬步同鏡禁高速平移、主動進攻禁 `slide/skid`，接地靜態必掛 `--anchor` | `fight-directing-contract.md`、`comfyui-dials-guide.md` |
| 4 | 防動態破圖身體機制句法：每記攻防寫「部位＋發力線＋目標」，不寫 `attacks fiercely` 這類空話；`<1.5s` 短鏡最多一個全身旋轉 | 本檔 §5、`validate_prompt.py` |
| 5 | 臉部特寫走 A 檔冷靜微表情（美型角色預設） | `facial-performance.md` |
| 6 | 雙語 1:1 切點同步編譯 | `output-format.md` |
| 7 | `python scripts/validate_prompt.py prompt.txt --duration N --check-sync`（打鬥加 `--strict-physics`），0 FAIL 才交付 | `SKILL.md` 3.2 |

**交付格式**（與 `SKILL.md` 3.1 相同）：中文導演母稿 → English H3 Prompt（單一 code block）→ 建議渲染指令（含 `--preset` 與雙軌秒數）。最後附一行驗證結果，例如「validator：0 FAIL／1 WARN（刀路佔比 58%，已知取捨）」。

軌道 A **不主動啟動 GPU**：除非使用者在訊息裡要求「直接生成影片」，否則只給渲染指令。

## 3. 軌道 B · 階段 1：輕量基本選項詢問（四大維度）

### 3.1 話術模板

先用一句話說明現在在做什麼，再給四個維度。每個維度都標好推薦預設，使用者可以只回「全用推薦」或「1-A 2-B 3 照推薦 4-B」。

```text
我先幫你把這場戲的骨架定下來，四個問題，直接回代號就行（或說「全用推薦」）：

1｜戰鬥種類與載體
  1-A 雙人冷兵器高燃死鬥（推薦：你給了兩張持刀角色圖）
  1-B 徒手／混合近身格鬥
  1-C 單人蓄勢毀滅大招／氣場覺醒
  1-D 巨獸／機甲以小打大
  1-E 參考片逆向拆解與復刻

2｜時長與節奏密度
  2-A 15 秒五段完整起承轉合（推薦）
  2-B 8–10 秒快切連續對轟，或無停頓 ULTRA_SPEED
  2-C 超過 15 秒的多段拼接長片

3｜核心看點、特效風格與勝負走向（可多選，也可以自己寫）
  看點：雙色刀弧光軌對撞／A 周身雷火或暗金鬥氣環繞／0.25s 黑白衝擊幀＋震屏頓幀
  勝負：A 逆轉破防擊敗 B（推薦）／勢均力敵對衝收尾／B 勝

4｜手頭素材與交付方式
  素材：角色圖＋空景圖 → Ref2VA 六欄位（推薦）｜只有首幀 → I2VA｜什麼都沒有 → T2VA 純文生
  交付：4-A 只要最終中英提示詞（推薦）｜4-B 確認後直接送本機 ComfyUI 生成影片
```

### 3.2 預填與推薦規則

- **已講過的不再問**：使用者訊息裡已經有的維度，直接寫成「已定：1-A 雙人冷兵器（你指定的）」，只剩沒講的才列選項。
- **推薦要有理由**：用素材的具體特徵說明（「兩人一紅一藍，剛好做雙色刀弧」），不要說「效果比較好」。
- **素材決定格式**：有角色圖與空景圖 → Ref2VA；只有一張完整首幀 → I2VA；什麼都沒有 → T2VA，並在階段 2 補問角色四維外觀（髮色、上衣、下身、鞋，見 `guided-mode.md` §4）。
- **只有參考圖、沒有方向**：先依 `guided-mode.md` 的情境 S1–S6 挑 3 個最合適的，換算成維度 1、2 的推薦值。

### 3.3 選項 → 上游與執行層的對應

| 維度 1 選項 | 時長預設 | 主載體 | 預設 Preset | 雙軌重點 |
|---|---|---|---|---|
| 1-A 雙人冷兵器 | 15s 五段 | 刃器／長柄 | **P9**（雙色刀弧）或 **P7** | P9：`--closeup` 鎖臉、正軌 ≤ `+0.29`、二採 off；P7：`--burst +0.65` 交鋒、`--anchor -0.55` 特寫 |
| 1-B 徒手／混合 | 15s 五段或 8s | 徒手＋可見兵器 | **P7** | 交鋒 `--burst +0.65`、重擊 `--hitstop -1.8`（0.25s） |
| 1-C 單人大招 | 15s 或 8s | 能力型 | **P8** | 開陣 `--anchor -0.65` 釘樁、破空 `--burst +0.80` |
| 1-D 巨獸／機甲 | 15s | 四足巨獸／機械載具 | **P7**（騰空段 `+0.80`） | 尺度參照見 `monster-scale.md`，著地後 `--anchor -0.30` |
| 1-E 逆向復刻 | 依參考片 | 依參考片 | 依拆解結果 | 走 `reverse-and-remix.md`：1 復刻＋2 衍生 |

## 4. 軌道 B · 階段 2：《影片內容與時間軸主要動作概要》（強制審閱閘門）

收齊階段 1 後，先在內部跑完上游導演內核（事實帳本、載體路由、九環因果鏈、姿態—位移防滑），**只交這份概要，不交英文 Prompt、不送 GPU**。

### 4.1 標準模板

```markdown
## 《影片內容與時間軸主要動作概要》

**對陣設定與視覺錨點**
- 站位軸線：左 A（{角色 A 名稱}）／右 B（{角色 B 名稱}），機位鎖在兩人連線同側 180° 不越軸
- 武器載體：A {兵器／能力}；B {兵器／能力}（雙方裝備與能量色互不污染）
- 專屬配色：A {鬥氣／刀弧色}；B {鬥氣／刀弧色}
- 場景壓縮元素：{柱廊／台階／斷崖／竹林}——把空間壓小、逼出連續互動
- 表情分檔：{A 檔冷靜微表情／B 檔咆哮}

**逐秒時間軸主要動作表**

| 鏡 | 秒數 | 誰對誰、什麼招（部位＋發力線＋目標） | 氣場／環境破壞 | 運鏡 |
|---|---|---|---|---|
| 1 | 0.0–{t1}s | {開場半秒內首接觸} | {火星／碎石／水牆} | {側面中景推進} |
| 2 | {t1}–{t2}s | {變軸首中或對方反壓} | … | … |
| 3 | {t2}–{t3}s | {冷靜微表情特寫＋氣場爆發} | … | {平滑推進特寫} |
| 4 | {t3}–{t4}s | {三高度拆招換位} | … | … |
| 5 | {t4}–15.0s | {不可逆結果定勝負} | … | {中景保持進行中位移} |

**預計渲染與滑塊策略**
- Preset：{P7／P8／P9}；二採 `--hires-dials {phase-motion／off}`
- 正軌 `--burst`：{秒數區間:強度}（交鋒段）
- 負軌 `--anchor`：{秒數區間:強度}（特寫鎖臉／接地定樁）
- 頓幀 `--hitstop`：{0.25s 區間}（重擊卡肉＋衝擊閃幀）
- 預估運動預算：base {+0.30}、交鋒峰值 {+0.95}（地面 ≤ +0.98）

**已知風險**：{一句話，例如「第 4 鏡三招 2.8s，若出片太擠可刪中段招」}

請問同意照這份分鏡概要推進，還是對哪幾秒的招式、鬥氣特效或勝負結果有調整建議？
```

### 4.2 填表硬規則

1. **鏡長**：雙人實戰每鏡 `2.2–2.8s`；末鏡 ≤ 總長 30%；首接觸 ≤ 0.5s。
2. **每列一件主動作**，且結尾有狀態變化（退了、斷了、碎了），不寫「兩人對峙」。
3. **招式寫實體**：部位＋發力線＋目標（「B 旋身掃腿掃 A 前踝」），不寫「激烈交手」。
4. **三條結構鐵律**要看得到：至少一次逆轉、空間被壓小、一個不可逆後果。
5. **滑塊秒數跟著切點走**：慢變軌（`--anchor`／`--burst`）邊界放在切點前 `0.25–0.35s` 起坡；鏡內轉折（例如特寫後才爆發）要在概要裡寫出轉折秒數；`--hitstop` 只畫 0.25s 窄脈衝。
6. **最後一句一字不改**：「請問同意照這份分鏡概要推進，還是對哪幾秒的招式、鬥氣特效或勝負結果有調整建議？」然後結束這一輪回覆。

### 4.3 回饋處理

- 使用者改某幾秒 → 只改那幾列，但**重交整張表**（秒數連動要看得到），再問一次同一句確認。
- 改動牽涉載體（例如「改成徒手」）→ 回到 §3.3 重選 Preset，並在概要的滑塊策略欄標示「已改」。
- 使用者回「OK／可以／照這個」才算通過閘門；「嗯」「再看看」不算。

## 5. 軌道 B · 階段 3：定稿編譯、自動檢核與出片

1. **編譯**：依通過的概要寫中文導演母稿與 English H3 Prompt，鏡數、秒數、招式、勝負與概要 1:1 一致（概要是合約，編譯時不得偷改招式）。
2. **防破圖自檢**（`validate_prompt.py` 會抓，但寫的時候就要避開）：
   - 空泛打鬥句（`attacks fiercely`、`fights intensely`、`epic battle`、`trade blows`）出現時，同一鏡必須有身體機制詞（重心、腳跟、轉胯、肩肘腕膝），否則 WARN。
   - `<1.5s` 的短鏡裡，`spins／flips／somersaults／whirls／cartwheels／twists mid-air` 合計 ≥4 個 → WARN（H3 會肢體融化、多出手腳）。
3. **驗證**（0 FAIL 才往下）：
   ```bash
   python scripts/validate_prompt.py prompt.txt --duration 15 --check-sync --strict-physics
   ```
4. **交付或出片**：
   - 選 4-A → 交中文母稿＋English Prompt＋渲染指令，附驗證結果。
   - 選 4-B → 送本機 ComfyUI：
   ```bash
   python scripts/render_comfy.py --engine selflift \
     --unet Minimax-h3_Singularity_x_10Eros-Max_PRISM_int8.safetensors --dmad 0.8 \
     --scheduler simple --steps 14 --transition 6 --lowres-scale 0.6 --chunks 4 \
     --hires-dials phase-motion --preset P7 \
     --burst 0.0:5.5:0.65 --anchor 5.5:8.1:-0.55 --burst 8.1:12.0:0.65 \
     --hitstop 12.2:12.45:-1.8 --anchor 12.6:15.0:-0.45 \
     --prompt prompt.txt --ref hero.png --ref villain.png --ref scene.png \
     --seconds 15 --seed 7101 --stage final --job duel_v4 --out out/duel_v4.mp4
   python scripts/measure_motion.py out/duel_v4.mp4 --fps24 --symmetry --footplant
   ```
   先用 `--dry` 看一次 `[dial-physics]` 預算行，確認交鋒段 `burst_eff` 地面 ≤ `+0.98`。

## 6. 完整對話範例（軌道 B，15 秒雙人刀槍）

**使用者**：用 h3-combat-impact 幫我設計一段刀客打槍客的戲，我有兩張角色圖和一張廊柱空景。

**階段 1（預填後只問剩下的）**：

```text
已定：1-A 雙人冷兵器（刀 vs 長槍）｜素材：兩張角色圖＋廊柱空景 → Ref2VA 六欄位
剩三個問題：
2｜2-A 15 秒五段（推薦）／2-B 8–10 秒快切
3｜看點：A 赤紅鬥氣環繞爆發＋0.25s 衝擊頓幀（推薦）／雙色刀弧對撞；勝負：A 逆轉破防擊敗 B（推薦）
4｜4-A 只要提示詞（推薦）／4-B 確認後直接送 ComfyUI
```

**使用者**：全用推薦，最後送 ComfyUI。

**階段 2（交概要後停下）**：

**對陣設定與視覺錨點**
- 站位軸線：左 A（赤衣刀客）／右 B（黑甲槍客），機位鎖在兩人連線同側 180° 不越軸
- 武器載體：A 單刀反握；B 長槍（刀弧與槍影互不污染）
- 專屬配色：A 赤紅鬥氣與刀弧；B 冷銀槍影
- 場景壓縮元素：雨中廊柱——柱距逼出貼身拆招與繞柱換位
- 表情分檔：A 冷靜微表情；B 咬牙低吼（不寫猙獰誇張臉）

| 鏡 | 秒數 | 誰對誰、什麼招 | 氣場／環境 | 運鏡 |
|---|---|---|---|---|
| 1 | 0.0–2.6s | 開場半秒內 A 後腳蹬碎青石貼地突進，右手反握刀撩斬 B 前膝；B 橫槍桿下壓硬架 | 刀槍交擊火星炸裂 | 側面中景推進 |
| 2 | 2.6–5.8s | B 擰腰旋身掃腿掃 A 前踝逼退半步，接連環兩記突刺壓向 A 胸口 | 槍尖破風捲起落葉 | 橫移跟拍 |
| 3 | 5.8–8.4s | 特寫 A 眉峰平靜、薄唇微闔，周身赤紅鬥氣環繞爆發，刀背一磕震偏槍尖 | 赤紅氣浪推開雨幕 | 平滑推進特寫 |
