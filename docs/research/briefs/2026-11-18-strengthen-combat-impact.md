### 1.2 現有方法論的核心（不要弄丟）

- 六拍打擊（蓄／觸／停／洩／退／收）＋三條比例鐵律
- 力場四通道（光／空氣／物質／粒子），一次最多開三個
- 16 招具名動作＋**配額制**（15 秒刀路上限 8 次）
- 三種節奏模式：六拍／連續對轟／ULTRA_SPEED（互斥）
- 三條設計原則：必須有交換、把空間壓小、給一個後果
- 參考圖保真 9 類特徵＋畫風錨 ≤3 個（錨多了會變靜止圖）
- 表情＝肌肉動作，不是形容詞
- 衝擊幀：同一段高速動作裡寫 `for two frames` 會炸成 23 幀 → 後製合成
- 量測：開場 0.8s ≥ 中段 50%、末 2s÷中段 ≥ 60%、最長低潮 ≤0.8s、峰值格 ≥4
- 輸出契約：只給一個 code block、官方三欄／Ref2VA 六欄、validator FAIL 必修

### 1.3 我判定的缺口（請你驗證或推翻）

1. **只有一種輸出格式（官方）**。老大自己的 `/h3-screenplay-prompt` 與 journal 都證明「劇本式／自含式長段」在 hosted / 長段 / 音樂驅動場景更強；但 repo 沒有格式選擇器，也沒有劇本式契約。
2. **沒有「可整句搬」的鏡頭塊庫**。h3-fight 的價值不在方法，而在「出過好片的句子＋出處＋檢查門檻」。本 repo 有 16 招與模板，但沒有可追溯的成片語料庫。
3. **沒有跨段狀態帳**。h3-fight 的「打壞的東西只寫剩下的樣子／新人物從畫外進來／不釘尾幀」是硬需求；本 repo 的 `fl2va-chain.md` 只講接縫，沒有道具／服裝／場景狀態的 ledger。
4. **沒有資產生產規範**。參考圖要三分之四側身戰鬥姿勢、主角朝右對手朝左、把想要的顏色與光效畫進圖——這些直接決定 Ref2VA 成敗，現在只寫「9 類特徵」。
5. **沒有音樂／onset 模組**。journal 半數案例是音樂先行；本 repo 完全沒有節拍網格與卡點寫法。
6. **衝擊幀只有後製一條路**。screenplay skill 的實測是「每張 0.3–0.45 秒、4–6 張、寫進提示詞，出片後剪到 0.1 秒」；與本 repo 的「後製 2 幀」不是矛盾，是兩條可選路徑，但文件沒說清楚何時用哪條。
7. **SKILL.md 已經 39 KB**。再加東西會稀釋注意力；需要 IA 重構（入口變薄、決策樹前置、細節下沉）。

### 2.1 外部 A/B 證據（不是我們測的，標 sourced）

- **SeedRouter**（H3 麵包店，4 段×1 seed）：普通提示詞 vs 官方三段 → 同樣可用；關掉 Context-IR 改寫則鏡頭與聲音混音改變。→ 格式本身不是品質開關，**後端有沒有改寫器**才是。
- **ArtArch #1 密度**（Seedance 2.5，6s，1v1，無共用 seed）：111 字 brief vs 270 字分區控制塊 → 密度讓**動作順序**更接近腳本，但「三次打擊」這種可數事件兩邊都沒做到；運鏡與構圖照樣漂。
- **ArtArch #2 brief vs checklist**（同模型、同素材）：兩種結構**丟失不同的拍**——checklist 保住「走進畫面」、丟掉「拉拉鍊」；brief 保住手部動作鏈與臉（12/12 幀有臉）、丟掉入場。→ 散文長於「連續動作鏈」，表格式長於「離散事件」。

這三條合起來的推論（請你判斷對不對）：**格式要按「這段最怕丟什麼」選，不是按「哪個比較專業」選。**

## 3. 我想做的改動（候選清單，請逐項給採納／不採納＋理由）

**A. 加第二輸出契約「劇本式」＋格式選擇器**
- 官方格式保留為預設（本地 ComfyUI／要精確切點）。
- 劇本式（中文）用於：開場節拍、禁止項多、衝擊幀、單鏡長動作、hosted 端點。
- 選擇器放在 SKILL.md 最前面，用「這段最怕丟什麼」當判斷軸。

**B. 台詞與切點精度分工**
- 要硬切準時 → 官方骨架＋英文 `[Shot N] At 00:02.300, hard cut`。
- 要開場不靜、效果聽話 → 劇本式。
- 這個分工寫成表，而不是「二選一意識形態」。

**C. 參考鎖＋可重複部件**
- 把「走路／電／煙／血霧」這類會在時間軸反覆出現的東西，集中寫成一個 block，時間軸只寫何時出現。
- 參考鎖明寫「只取身份、臉、衣服；參考圖站姿與底色不用」。

**D. 衝擊幀雙路徑矩陣**
- 路徑 1：後製 2 幀（現有，最準）。
- 路徑 2：in-prompt 4–6 張卡片×0.3–0.45s，出片後剪到 0.1s（screenplay 實測）。
- 給「哪個後端／哪種衝擊（斬擊 vs 拳擊 vs 爆炸）」的選擇表。

**E. 多段連續性帳（continuity ledger）**
- 每段開頭一張小表：場景狀態／道具位置與損壞／服裝狀態／人物位置與朝向／上一段末幀。
- 「打壞的東西只寫剩下的樣子」寫成硬規則。
- 首帧釘法：釘首不釘尾（h3-fight 實測尾幀會壓死打法）。

**F. 鏡頭塊庫 + 檢查器 v2**
- 從本 repo 的 10 份 examples 與 7 支 showcase 收割「出過片的句子」，建 `library/`（JSON：用途／打法／中文要點／英文原句／出處／等級）。
- `validate_prompt.py` 加：每鏡字數、招牌句數、相鄰鏡四軸差異、刀路配額、表情肌肉、末鏡占比（部分已有）。
- 檢查門檻校準規則：**好片全過、已知爛片全不過**（要真的跑一遍 10 份 examples 與歷史失敗版）。

**G. 音樂／onset 模組（可選）**
- `scripts/onset_grid.py`：輸入音檔 → 輸出 BPM／onset 時間表 → 提示詞的切點吸附建議。
- 只做「有音檔」的情况；沒有音檔時退回現有節奏模式。

**H. 資產生產規範**
- 角色圖：三分之四側身、戰鬥預備姿勢、主角朝右對手朝左、想要的顏色與光效畫進圖、白底或灰底、不帶武器時雙手空空。
- 場景圖：與角色圖同機位邏輯、要拍的視角就畫那個視角（journal：文字拉不動場景）。
- 交付前用 `measure_staging.py`／目視檢查。

**I. SKILL.md 重構（IA）**
- 入口 ≤ 200 行：決策樹、格式選擇器、六拍一句話、交付契約、檢查指令。
- 其餘下沉到 references，並新增 `references/screenplay-format.md`、`references/continuity-ledger.md`、`references/asset-pipeline.md`、`references/music-onset.md`。
- 旧文件不刪，只加 front-matter「何時讀我」。
